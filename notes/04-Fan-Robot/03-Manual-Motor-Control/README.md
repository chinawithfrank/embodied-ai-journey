# 先别让它自己走：保留相机，手动点动两台 N20

相机已经装好，我不想为了测试电机再把那一堆线拆掉。这次目标很小：**在手机上按住一个按钮，让其中一台电机转；松开就停止输出。** 先确认供电、接线、方向和停止行为，再谈视觉跟随。

硬件是已有的 ESP32-S3 N16R8、BY-OV2640-V1.5 摄像头，再加一块 DRV8833 驱动模块和两台标称 6V、60转/分钟的 N20 减速电机。这里不是让相机指挥电机，也没有启用风扇。

## 这一次“不影响相机”是什么意思

- 原相机排针和 3.3V 供电不动；新增四根逻辑控制线，另走电机电源。
- 新草图 [`esp32_motor_manual`](../../../ros_ws/src/fan_robot/firmware/esp32_motor_manual) 同时运行相机网页和电机控制；原来的 `/health`、`/capture`、81端口视频继续保留。
- 相机实现抽到 [`camera_app.hpp`](../../../ros_ws/src/fan_robot/firmware/esp32_camera/camera_app.hpp) 共用，原 `esp32_camera.ino` 仍可单独编译为只看相机的固件。相机私有配置不覆盖、不重新分配引脚。
- 控制页单独用82端口，停机检查用独立任务，不把电机的心跳检查放进长时间发送视频的处理函数。
- **同一块 ESP32 一次运行一个固件**。本节是 Arduino“相机 + 手动电机”版本，不包含上一节的 ESP-IDF 手部推理。若目前刷的是手部检测，刷本节后它暂时被替代，不是两个固件同时运行。上一节代码没有修改，之后可再整合。

这能避免软件引脚冲突，但不能保证接上任何电源都不影响相机。电机启动的电流和干扰仍可能让 ESP32 重启；供电和布线也属于实验的一部分。

## 1. 独立电机供电：本次用三节干电池，不用开发板硬带

用户已确认实际供电方案：**三节1.5V干电池串联，标称4.5V，使用电池盒自带开关，正负输出线由用户识别**。照片中额外的线来自开关，不能再据此认定用户不清楚极性。此处记录的是用户确认的接法，不是本机已经测得的电压或启动电流。

这套电源可以先用于单台6V N20的短时空载点动：电压低于电机额定值，也在DRV8833的工作电压范围内。能否可靠启动，尤其两台同时启动，仍取决于电池种类、新旧、接触电阻和电机电流。先一台、再另一台，最后才一起测试；不要期待额定60rpm，也不需要为了凑6V就立刻改电池方案。

其他复现实验的读者若手里只有开发板、驱动板和电机，仍需先准备合适的独立电源和能快速断开的开关，不应从ESP32取电。

实物补充：用户还有一块标称LR7843的“隔离MOSFET模块”。**它是电子开关，不是电源，也不是降压模块**；商品名中的“隔离”不代表它能提供隔离电源。即使接上它，仍需要电池或稳压直流电源。当前DRV8833已经承担电机开关、调速和换向，这一步不需要再串入LR7843，尤其不要把它串在ESP32与DRV8833的共地线上。商品链接未能读取，不据此断言该模块的具体端子、电流能力或隔离电路。[IRLR7843器件资料](https://www.infineon.com/assets/row/public/documents/24/49/infineon-irlr7843-datasheet-en.pdf)

若另有可限流稳压电源，可用它做更可控的测试；没有则按本次4.5V电池方案先做短时空载验证，不必为此把未知MOSFET模块加进来。不能仅凭“6V、60rpm”推断堵转电流或供电能力；正式装车前仍需查询或测量启动/堵转电流，核对模块的连续电流和散热条件。

- ESP32 仍由原 USB 供电；DRV8833 的电机电源端接独立电源，**不接 ESP32 的3.3V，也不从开发板的5V针脚取电**。
- 独立电源负极、驱动板GND和ESP32 GND必须共地。电机的大电流回路直接回电源，不绕过 ESP32 或细长面包板导线。
- 不要将独立5V/6V正极接到ESP32的3.3V脚；也不要把它并接到USB的5V上。
- 两节锂电串联满电8.4V，不是这对6V电机的直接供电方案。不能因为驱动芯片能承受某个电压，就认为电机也能承受。
- 电机电源回路加易够到的物理开关，保险/限流按实际电机选。网页停止不能代替物理断电。
- 驱动板附近按模块说明做好去耦；若缺少储能电容，可在确认极性和耐压后加合适的电解电容，例如100～470µF、耐压至少10V，并配合陶瓷去耦。电机线和摄像头信号线尽量分开、缩短。

```text
原 USB ───────────────→ ESP32 ── 原相机接线 ──→ OV2640
                         │ GPIO1/2/38/39
                         ↓
电池盒4.5V正极 ─ 自带开关 → DRV8833 VCC ─ H桥输出 ─→ 两台电机
电池盒负极 ─────────────→ DRV8833 GND
                         └──────── ESP32 GND
```

DRV8833是两路H桥驱动，不是传感器：ESP32只给它低功率控制信号，由它向电机提供电流。芯片支持2.7～10.8V电机电源，但这不是本项目建议给电机的电压；具体模块的电流能力不能直接照搬芯片宣传值。[TI 官方规格与供电说明](https://www.ti.com/lit/ds/symlink/drv8833.pdf)

## 2. 保留原相机线，只新增这些连接

**先拔掉USB并断开电机电源，再接线。下表按信号名连接，不是排针物理位置图。** 用户已提供正反面照片：引脚面左列从上往下可见 `IN4、IN3、GND、VCC、IN2、IN1`，右列可见顶部 `EEP` 字样、`OUT1～OUT4` 和底部 `ULT` 字样；板上还有 `J1` 与 `en/sleep` 标记。照片确认了丝印，不代表已确认J1连通状态、真实芯片来源、持续电流能力或使能电路。

这版板把通用说明里的四个控制输入写作IN1～IN4，电源端写作VCC。用户随后提供的模块说明确认：VCC接电源正极，OUT1/2对应IN1/2，OUT3/4对应IN3/4。以下按这块模块的说明对应到程序，不能把相似外观的其他板原理图当成这一块已经做过的通断测量。

| 当前模块丝印（通用名称） | 接到哪里 | 含义 |
|---|---|---|
| IN1（AIN1） | ESP32 GPIO1 | 电机A控制1 |
| IN2（AIN2） | ESP32 GPIO2 | 电机A控制2 |
| IN3（BIN1） | ESP32 GPIO38 | 电机B控制1 |
| IN4（BIN2） | ESP32 GPIO39 | 电机B控制2 |
| OUT1、OUT2（AOUT1、AOUT2） | 第一台N20的两根线 | 模块说明确认对应IN1/2；不接ESP32；对调两根电机线会改变方向 |
| OUT3、OUT4（BOUT1、BOUT2） | 第二台N20的两根线 | 同上，首次只接一台短点动核对路数 |
| VCC（电机电源VM） | 独立电机电源正极 | 模块说明确认；不是要求接ESP32的3.3V逻辑电源 |
| GND | 独立电源负极 + ESP32 GND | 共地 |

GPIO是编号，不是排针上从左数的第几根。1、2、38、39不占当前相机的4～14、16～18、21，也避开原生USB的19/20、N16R8内部存储相关引脚和常见启动配置脚。仍需确认这些针没有被你后来接的其他外设占用。

### SLEEP、FAULT 与不同模块的差异

用户提供的模块说明第5条确认：**J1默认连接，将EEP拉高；EEP低电平才休眠，外部控制休眠前需断开J1。** 第6条确认ULT在过流或过热保护时输出低电平。因此本块板保持原厂J1连接、EEP和ULT不接ESP32，保留 `sleep_pin = -1`、`fault_pin = -1`。不要另加GPIO去对抗板上的固定高电平，也不要因指示灯亮就认为输出已经正常；指示灯不是电压测量。其他型号模块仍需核对自己的说明和电路。

- 若模块有 `nSLEEP` / `SLP`：低电平休眠，高电平唤醒。推荐在确认模块电路后接GPIO40，并用10kΩ下拉保证启动期间休眠，在本地配置把 `sleep_pin` 改为40。若它已在板上固定拉高，不能再盲目接一个GPIO强拉低，先核对电路。
- 若没有引出休眠脚：保持 `sleep_pin = -1`，确认模块已按其说明使能。建议四个输入各加10kΩ到GND，确保ESP32复位/未配置时不悬空；DRV8833芯片虽有内部下拉，模块附加电路仍需要核对。
- 若模块有 `nFAULT`：可选接GPIO41并把 `fault_pin` 改为41，确认输出确为开漏、上拉到3.3V。不要把被模块上拉到电机电压的信号直接接ESP32。默认 `-1` 表示软件没有读取故障脚，不等于没有故障。
- 这次已补充VCC丝印的对应关系；后续若更换为带 `STBY` 或其他名称的板子，**不要把未知电源端和未知控制端直接照表替换**。

## 3. 先理解为什么它能正反转

H桥改变电机两端电压的方向。对每路DRV8833，两个输入都为低时输出断开、滑行；一高一低决定方向；本实验对其中一端做PWM、另一端保持低，改变的是驱动占空比。

“停止”是撤去驱动、允许滑行，**不是立即锁住机械轴**。N20上的“60转/分钟”是指定条件下的标称值；没有编码器，程序不知道实际转速。20%PWM不等于12rpm，也不是20%的电流限制。启动和堵转时仍有电流峰值。

## 4. 配置：默认禁止电机输出

入口是 `firmware/esp32_motor_manual/esp32_motor_manual.ino`。完整保留整个仓库，不能只复制这一个 `.ino` 到别的空文件夹，因为它会引用旁边的相机共用实现。

在这个新草图目录中，将 `motor_config.example.h` **另存为** `motor_config.local.h`，内容最初为：

```cpp
namespace motor_settings {
constexpr bool wiring_confirmed = false;
constexpr int input_pins[] = {1, 2, 38, 39};
constexpr int sleep_pin = -1;
constexpr int fault_pin = -1;
}
```

确认实际模块端子、电源极性、共地和四根逻辑线之后，才把 `wiring_confirmed` 设为 `true`。是否使用40/41按上节核对；不能因为示例给了数字，就认定你的模块已经接好了。保留示例中的 `#pragma once`。私有文件已被Git忽略，旧相机的 `camera_config.local.h` 不改。

程序启动仍保持锁定，不会因为配置为true就自己转。还会检查重复/冲突GPIO；这个检查能发现配置错误，不能检查你实际插错了哪根线。

## 6. 第一次点动：一台一台来

1. 固定电机本体，轴上不装风扇、不靠近衣物手指；若已有轮子，把轮子架空。**不要用手捏住输出轴做堵转测试。**
2. 先只接电机A，关闭电池盒开关并断开USB接线；电池盒开关后的正输出接VCC，负输出接GND，另用逻辑地线连接ESP32 GND。接好后先给ESP32接原USB、确认程序锁定，再打开电池盒开关；相机原线不动。
3. 占空比先用默认20%。点击“解锁一次”，5秒内按住“A正转”约0.2～0.5秒后松开。确认停止输出，再重新解锁测试“A反转”。3秒是软件保护上限，不是建议每次都运行到上限。
4. 如果只有嗡声但不动，立即松开、断电检查。可能是静摩擦、电源限流或接线问题；不要长时间憋转，也不要一下把功率拉满。确认电气条件后再小幅提高到30%等测试。
5. 电机A正常后，再测试电机B，最后才测试“两台正转”。A/B正转只是接线约定，不一定等于小车向前，两侧装到车上后可能需要交换某台电机两根线。
6. 同时打开相机画面，观察电机启动时有没有花屏、重启、掉线。若有，先断电检查供电和布线，不是通过关闭摄像头来掩盖问题。

每次松开、切到后台、关闭页面或点击停止都会请求锁定；再动需要重新解锁。超过3秒即使一直按住也锁定，避免桌面试验无意持续运行。解锁后没有动作，5秒后自动重新锁定。

### 6.1 实测记录：直接接线能转，网页40%却不转

2026-10-28，用户确认电机直连三节干电池能转；驱动板IN1接ESP32的3V3、IN2接GND时也能转，但恢复GPIO控制后网页40%不能起动。这确认了当时电源、电机和驱动桥可以工作，却不能证明GPIO控制或PWM已经正常。

为区别起动力度不足与GPIO输出问题，2026-10-28的版本增加独立的 **A正转100%诊断**，当时普通点动仍限于40%，不自动加起动冲击。诊断按钮保留在当前版本中：

1. 关闭电池开关、拔掉USB。撤掉IN1到3V3以及IN2～IN4到GND的临时测试线，恢复IN1/2/3/4到GPIO1/2/38/39，共地不变；只连接电机A并固定空载。
2. 电池保持关闭，重新编译上传 `esp32_motor_manual.ino`，刷新82端口页面。仅修改源码或刷新网页不会更新板上固件。
3. 仅用于本次4.5V电池和6V N20：开启电池开关，重新解锁后按住诊断按钮一次。该指令固定A正转、B停止，通过LEDC停止PWM并将活动输出保持高电平，实现持续驱动。
4. 板端从接受指令开始500ms限时，到时清零并锁定；独立任务约20ms检查一次，实际撤销有调度延迟，不是精确的硬件500ms脉冲。松手/停止仍可提前撤销。重复诊断、普通心跳不能续期，反转等待仍有效。
5. 若能转，说明当次GPIO持续驱动路径有效，应继续检查低占空比起动能力和PWM行为，不能仅凭一次测试断言PWM波形正确。若仍不转，而手工接3V3能转，重点检查GPIO编号、杜邦线、固件是否更新和输出配置。不要反复堵转或擅自提高电池电压。

`POST /api/diagnose` 只接收当前新解锁会话的 `session` 和 `sequence: 1`，不接受任意功率、方向、持续时间或双电机输出。到时状态为 `diagnostic_complete`。这仍是软件保护，物理电池开关须保持可触及；不改变相机接线或本地相机配置。

### 6.2 诊断能转后：逐步寻找可起动的占空比

2026-10-29，用户确认网页的100%诊断能让电机A转动。这比手工接3V3又多确认了一环：程序、GPIO和驱动桥的持续高电平输出路径，在这次测试中是有效的。因此不再反复给EEP加线，也不需要改相机接线。

但这个版本的100%是持续高电平，不经过中间占空比的PWM。因此**“100%能转”不等于“20kHz PWM波形正确”，更不能立即断定40%不起动只是静摩擦**。供电压降、起动条件和PWM行为都还可能影响结果。网页的 `sequence`、`a/b` 也只是软件命令，不是测量结果。

当前版本将普通点动范围从原来的10～40%扩展为 **10～100%**；刷新后仍默认20%，不自动满功率起动，也不提高电池电压。100%使用已通过A路实测的持续驱动路径，低于100%仍使用原来的20kHz PWM，便于只改变占空比做对比。松手、心跳超时、反转等待和3秒会话上限都保留；诊断按钮另有500ms限时。

1. 仍使用三节1.5V干电池和6V N20。保持现有GPIO接线，先只连接电机A、固定空载。关闭电池开关，再通过USB重新编译上传 `esp32_motor_manual.ino`，刷新82端口页面，看到滑块上限100%。不要覆盖自己的相机或电机本地配置。
2. 打开电池开关，选择60%，重新解锁，短按普通“A正转”0.2～0.5秒后松开。若只响不转，立即停止，不要等满3秒。
3. 60%不起动时，重新解锁，试80%。仍不转可用100%短点动作对照；记录每次“静止起动是否成功”，不是只看运行中能否维持。改变滑块时若正在点动会先请求停止，下一次仍需重新解锁。
4. 如果60%或80%能够起动，说明在该档位下PWM已经能够驱动这台空载电机。记录最低可起动档位，保留余量，但不要当成不同电池电量、负载和另一台电机的通用阈值。
5. 如果只有100%能转，不继续猜“电机坏”或“换更高电压”；下一步应检查PWM频率/输出及起动条件。当前改动只是扩大手动测试范围，不代表低速问题已经解决。
6. A路正反转及停止都验证后，再断电连接B，单独测试；最后才测试两台一起。A路的结果不代表B路、两台起动电流或摄像头抗干扰已经验收。

特别注意：100%指把电池供电持续施加到驱动桥，不是把ESP32的3.3V当成电机电源，也不是保证电机达到额定60rpm。这个范围按本次4.5V/6V配置测试；更换电源或电机后必须重新核对额定值，PWM百分比不是硬件限流或过压保护。

### 6.3 80%能转后：接上第二台，不急着落地

2026-10-29，用户确认：A路普通点动60%不转、80%能转。这说明PWM在80%这个档位能够驱动当前电机。80%是已验证的可起动档位，不是精确的最低起动阈值，也不代表B路或两台一起同样可靠。

程序已有B正转/B反转和两台正转/两台反转，不需要改代码或重新上传。网页刷新后仍默认20%，本轮需要手动选择80%。

1. **关闭电池开关、拔掉USB。** 保留A在OUT1/OUT2，把B的两根线接到OUT3/OUT4，不要将电机的一根线接GND。确认IN3到GPIO38、IN4到GPIO39；IN1到GPIO1、IN2到GPIO2保持不变。电池正极经开关到VCC，电池负极、驱动板GND、ESP32 GND共地。EEP和ULT不接，J1保持原厂连接。
2. 固定两台电机；若装好了轮子，先把车架垫稳、轮子悬空。先接USB、确认网页输出锁定，再开电池开关。原相机接线与USB供电不变。
3. 82端口设80%，解锁后短按 **B正转** 0.2～0.5秒，松开确认停，再解锁短按 **B反转**，A此时应不动。随后单测A正反转和松手停止。只响不转、发热或不按预期停止，立即关电池，不连续重复试。
4. 两路各自正常后，重新解锁，短按 **两台正转** 0.2～0.5秒，确认两台一起转、松手都停，再试两台反转。3秒是保护上限，不是建议时长。此处用普通按钮，不是仅驱动A的100%诊断按钮。
5. 若单独都能转、一起却不起动/变慢，或ESP32重启、画面花屏/掉线，先关电池，检查电池状态、开关触点、供电线和共地；两台启动对供电要求更高，不能由单台成功推定双台供电充足。不要提高电池电压或取消停机保护来掩盖问题。
6. 轮子保持悬空，检查左右轮是否会让车朝同一方向走。镜像安装时，“两台正转”不一定等于整车前进。需要交换某台电机的两根OUT线时，先关电池、拔USB；不改相机或GPIO控制线。

先验收两路空载正反转、双路同时运行和松手停止，再打开一个相机预览，观察电机启动有无干扰。B路、双电机和相机共存的实测结果仍待反馈，不因多接了一台就将整机标为完成。

## 7. 为什么还要“心跳”和会话编号

浏览器消失时不一定能发出最后一个“停止”。所以按住期间每次请求得到回应后，页面约150ms再发下一条指令；板上独立任务约20ms检查一次。600ms没有新有效指令，就清零输出并锁定，不等网页回来。

每次解锁都有新会话编号，每条运动命令有递增序号。松手后的迟到请求、上一会话的请求、重复/倒序命令都不能恢复运动。方向切换先撤掉两路输出，再留出100ms反转等待。停止再解锁也保留方向历史，不能用重开会话绕过等待。

会话编号防止旧命令误用，不是登录认证。只在可信本地热点、单个操作者下调试，不做公网端口映射；不要把“有会话编号”等同于实现了远程访问安全。

这些是软件约束，不是安全认证：任务卡死、驱动故障、供电问题仍可能让软件失效。600ms也不是机械停止时间的承诺，实际还涉及任务调度、驱动和惯性。物理电源开关必须保留。

## 代码与排错入口

| 文件/状态 | 意义 |
|---|---|
| `motor_guard.hpp` | 与硬件无关的解锁、心跳、限幅、会话、反转等待和超时逻辑 |
| `motor_server.hpp` | GPIO校验、LEDC timer1 / channel2～5、独立任务、82端口API |
| `motor_page.hpp` | 按住操作和可选相机预览；没有自动跟随逻辑 |
| `/api/status` | `ready`是软件输出路径就绪，不是测到了VM、转速或真实电流；`a/b`是已提交的占空比指令 |
| `invalid_or_conflicting_motor_gpio` | 检查相机/USB/内部存储相关保留引脚和重复分配 |
| `requires_onboard_camera_clock` | 本版本只用于已确认的板载时钟相机，拒绝改变其他外部XCLK方案的共享时钟资源 |
| `heartbeat_timeout` / `session_timeout` | 超过指令租期或3秒运行上限，重新解锁前先检查原因 |
| `driver_fault` | 仅在配置故障脚后有效；断电检查过流、过热、欠压或接线，不要反复强行解锁 |

LEDC只使用timer1和channel2～5，不重设相机的timer0/channel0；当前相机实际使用板载24MHz振荡器。摄像头本身GPIO不改，手部识别工程也未接入任何电机输出。[乐鑫 LEDC 配置说明](https://docs.espressif.com/projects/esp-idf/en/v5.4.2/esp32s3/api-reference/peripherals/ledc.html)
