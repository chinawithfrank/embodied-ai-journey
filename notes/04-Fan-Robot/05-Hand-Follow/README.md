# 05 · 让履带、摄像头和风扇形成闭环

**当前本机模式：上电自动跟随。** 用户要求取消网页启用，私有 `settings.local.h` 已设置 `auto_start = true`。启动安全初始化、接线/标定检查通过后，设备自动等待新鲜手部目标；识别到手即开风扇，并按位置/尺寸控制履带。无须打开网页，不受网页心跳和 30 秒会话上限限制。下文的 30 秒和页面断联停机规则仅适用于 `auto_start = false` 的手动模式。

电池开关只切断执行器供电，ESP32 无电池状态检测；USB 供电时控制器已在运行。关闭电池再打开会恢复执行当时的控制指令，不能把电池切换当作清除网页停止锁定。网页“立即停止”保持锁定，按“恢复自动跟随”或重启 ESP32 才恢复；关闭网页和 Wi-Fi 断开不停止自主控制。仍在有物理围挡的区域使用。

刷写时必须关闭电机电池开关，等待刷完并启动后再接通。串口 `AUTO_START: tracking enabled; waiting for a fresh hand` 表示已进入自动等待。未检测到手、图像过期、输出异常仍停止，电机单脉冲时限保持有效。

本次用户确认相机、履带和风扇已能分别控制。这里新增 ESP32-S3 本机运行的手部跟随；不依赖电脑推理、云端服务或网页发送运动方向。网页只负责启停、续租和状态显示。代码已经加入，实物的转向、距离、延迟和联合供电仍需按下列步骤验收。

## 技术选择与边界

在现有 S3 上沿用 ESP-IDF 5.4.2 + ESP-DL HandDetect + FreeRTOS。视觉伺服使用归一化画面误差，以有界短脉冲闭环控制两条履带。这适合当前低帧率、无编码器、已知电机起转约需 80% PWM 的硬件。没有轮速反馈和稳定采样率前，不直接套轮速 PID，也不把 PWM 假定成线速度。此次没有引入 ROS 2、SLAM 或导航栈；将来加 Linux 上位机、编码器、测距和地图时可以接入，而控制接口不需要绑死在它们上面。

现有底盘只能前后和左右转，不能俯仰，所以“居中”首先指水平居中。手的垂直误差过大时显示 `adjust_hand_height`，停止输出，让用户调整手的高度或机械安装角度。若需要真正的二维瞄准，应新增俯仰执行器。

手框尺寸 `size = sqrt(框宽 × 框高 / (图宽 × 图高))` 是相对距离代理。相同手、相同姿势下，可近似认为距离比为 `标定 size / 当前 size`，但不能可靠输出厘米。张手/握拳、侧转、遮挡和不同人的手都会改变估计；本版只用于固定张手姿势的交互实验。后续可替换为掌部关键点尺度或 ToF 深度，不改执行层。

没有桌沿、障碍物和里程计传感器。短脉冲和超时不会提供防跌落能力；测试必须使用物理围挡或地面测试区，不能在开放桌沿自主运行。目标消失时原地等待，不盲目旋转搜索。

## 分层和扩展口

- 感知：`app_main.cpp` 采集、检测，发布带帧号和采集时间的 `Target`。多只手时禁止跟随，避免在多个目标间跳转。
- 行为：`autonomy/controller.hpp` 中 `HandFollower` 是无硬件依赖的状态机，输入 `Target`，输出左右履带的有符号占空比和风扇开关。
- 监督：`Supervisor` 管理会话、心跳与 30 秒运行上限；20ms FreeRTOS 执行任务独立于模型推理运行。画面失效也由执行任务检查，推理挂住时不依赖下一次推理来停机。
- 硬件适配：`autonomy/runtime.hpp` 把逻辑左右履带映射到实际 A/B 通道、方向符号和 PWM；复用原电机与风扇引脚配置。相机 LEDC timer 0 与电机 timer 1 / channel 2–5 分离。
- 界面：`GET /robot`；`GET /robot/state`；`POST /robot/arm`、`POST /robot/stop`、`POST /robot/heartbeat`。续租必须携带 arm 响应里的 `X-Robot-Session`，旧会话不能续租新会话。停止不需要 token，任何本地控制页都能停机。接口用于可信设备热点，非公网控制服务。

后续“吹气球”等行为应新增接受独立目标观测、返回 `Command` 的行为控制器，由唯一的行为选择器决定当前谁控制；不要另开任务直接写 GPIO。测距、避障、桌沿、驱动器故障可作为监督层的独立输入，并优先覆盖所有行为输出。当前只有 J1 常高、无 fault 输入的 DRV8833 接法被支持；其他 sleep/fault 配置明确拒绝启用，不能忽略故障线。

## 状态和输出规则

`disarmed → waiting_hand → aligning → ranging → settling → blowing`

- 水平偏差超过容差，左右履带相反方向短点动，先转向；未对准不前后移动。
- 水平合适后，手框太小前进、太大后退。
- 前后移动默认单脉冲 100ms，冷却 300ms；转向按水平偏差在 100～350ms 之间调整，冷却 150ms。重复帧不能开始新脉冲，运动期间采集的画面不能启动下一次运动。新画面仍偏向同侧时完成当前转向脉冲，但绝不延长原定截止时间；居中、越过中心、丢手时提前停机。
- 水平进入容差 0.12，退出容差 0.20；尺寸进入容差 0.04，退出容差 0.07，减少临界位置反复摆动。
- 启用会话内，只要检测到单个有效且新鲜的手就开风扇；转向、前后移动、等待稳定以及手偏高/低时都允许吹风。目标丢失、多手、过期、停止或会话到期则关闭。连续 3 帧位置与距离合适只代表底盘进入稳定状态，不再作为开风扇条件。
- 画面默认超过 1000ms 失效。输出任务每约 20ms 检查脉冲和过期时间；这不是硬件安全认证，调度延迟需要实测。
- 心跳每 250ms 发起，设备 1000ms 没收到有效续租自动撤销启用。断线后不自动恢复。每次最多 30 秒，需要再次主动启用。
- PWM、引脚冲突、配置或任务初始化失败时不允许启用。物理电池开关仍是最终断电方式。

## 标定和启动

新版本是在 `firmware/esp32_hand` 内增加可选功能，刷入后替代 Arduino 手动固件；不会在原 82 端口页面上自动出现。旧手动草图保留，离线检测默认仍不启用自主输出。

1. 先使用原手动固件，架空履带核实 **A 路是左履带，B 路是右履带**，记录使各履带前进需要的正负方向。确定相机和风扇朝向一致、风扇有护罩。先完成这一步再刷跟随固件。
2. 保留原来的 `camera_config.local.h`、`motor_config.local.h`、`fan_config.local.h`。程序读取旧目录中的这些文件，不自动修改接线。它们的 `wiring_confirmed` 必须为 true。
3. 在仓库根目录执行：

```bash
cp ros_ws/src/fan_robot/firmware/esp32_hand/main/autonomy/settings.example.h \
   ros_ws/src/fan_robot/firmware/esp32_hand/main/autonomy/settings.local.h
```

先保留 `motion_confirmed = false`。填写 `left_sign`、`right_sign`；倒装相机优先在 `camera_config.local.h` 同时启用 `vertical_flip` 与 `horizontal_mirror`，让图像在进入检测前旋转 180°，此时 `config.turn_sign` 保持 1；只有画面仍是额外的左右镜像时才单独校准该符号，避免重复反转。默认目标尺寸 0.35 仅供开始标定。

4. 使用已安装的 ESP-IDF 5.4.2 环境：

```bash
# 将路径替换成实际的 ESP-IDF 5.4.2 安装位置
. ~/Develop/esp/esp-idf-v5.4.2/export.sh
cd ros_ws/src/fan_robot/firmware/esp32_hand
idf.py menuconfig
```

在 `Fan robot: offline hand detector` 中启用 `Enable optional local Wi-Fi AP and browser preview` 和 `Enable local hand-follow controller`。保持 ESP32-S3、16MB Flash、8MB OPI PSRAM 的现有配置。

**刷写前关闭电机电池开关，USB 保持连接。** ROM 下载、复位期间应用程序尚未运行，软件停机逻辑不能保护该阶段。刷完看到 `BOOT_SAFE` 且相机正常后，再在履带架空的情况下接通电机电源，先验收未启用时不动作。

```bash
idf.py build
idf.py -p /dev/cu.usbmodemXXXX flash monitor
```

5. 连接 `FanRobot-Hand` 热点（默认密码 `fanrobot123`），打开 `http://192.168.4.1/` 查看框，再打开 `http://192.168.4.1/robot` 查看 `size/x/y`。在手掌张开、风扇朝向手且吹风距离合适的位置读多次 size，取稳定值填入 `config.target_size`。相机和风扇安装偏差应先机械修正；软件不知道真实风束方向。
6. 标定完成后，设置 `motion_confirmed = true`，重新编译刷入。在围挡测试区域，勾选确认并点“启用 30 秒”。第一轮只验证水平转向；若手在画面右侧时偏差反而增大，立即停止，检查 A/B、方向符号和镜像配置。
7. 确认转向正确后才验收距离。默认 80% PWM 来自此前起转测试，不代表速度已标定；从短脉冲、小误差开始。如 100ms 无法起动或位移太大，调整 `duty/pulse_ms/cooldown_ms`，不要直接加长连续运行。

本地自主配置被 Git 忽略，不共享设备的标定结果。浏览器本身可休眠，所以启用页必须保持前台；相机预览可放在另一窗口，切走启用页会停机。

## 验收清单

1. 上电、未启用、配置未确认：电机和风扇都不动作。
2. 手在左/右：只短转向，偏差逐步变小；方向反了必须停止修正。
3. 水平居中，手远/近：分别短前进/后退；手太高/低不移动。
4. 启用后伸手即开风扇，包括手未居中、距离未合适时；连续稳定 3 帧后履带保持停止。挪开手、加入第二只手后停风停履带。
5. 遮挡摄像头、断 Wi-Fi、关闭启用页、停止模型更新：分别验证目标丢失、租期和画面过期停机；恢复后不能自动重启过期会话。
6. 点击停止；30 秒会话到期；旧 session 的心跳不能复活输出。
7. 摄像头预览、推理、电机和风扇联合运行时，记录 processing_ms、画面 age、抖动和供电复位。若总推理延迟超过 1 秒，默认禁止移动，应先优化模型/采集，不直接放宽到数秒。

不连接硬件的回归测试：

```bash
python3 -m unittest discover -s ros_ws/src/fan_robot/tools/tests -v
```

控制器测试覆盖脉冲结束、冷却、新鲜帧、正反转、前后移动、稳定帧、迟滞、垂直限制、坏数据、镜像、会话隔离和租期上限。它们不能代替真实机器的方向、起动性能、停止距离和供电验证。

## 启动后电机持续倒转修复

用户报告在刷写后持续出现 `HAND not_found` 日志时，右履带仍一直后退。检查本地配置发现 `motion_confirmed = false`；旧 `begin()` 在该条件下提前返回，没有初始化四路电机 GPIO，且旧调用发生在相机初始化之后。这是明确的软件缺陷，与用户所述未启用却持续运动的现象吻合；具体引脚电压尚未测量。

修复后，`app_main()` 第一阶段就对接线已确认且无冲突的执行器设置停止电平：先预置输出锁存值，再设 GPIO 输出/下拉，再重申停止电平。停机初始化不受自主功能开关、运动标定、相机成功与否影响；初始化失败中止后续启动。正常运行的执行任务在未启用时也重申停止。启动成功输出 `BOOT_SAFE`，它表示软件调用成功，不代表外部电压测量。

保持 `motion_confirmed = false` 重新编译刷入，先验收无目标、出现手、打开网页但未启用时都不转，再继续标定。21 项主机测试通过，增加了 GPIO 锁存/输出顺序、失败后仍处理其他引脚、低有效风扇关闭电平测试。实际停止效果待重新刷写后验收。

现有驱动板 J1 将 EEP 常拉高，复位/ROM 下载时仍缺乏硬件禁能保障。因此任何刷写、复位测试都先关闭电机电池开关。若需要在电机供电不断开的条件下保证上电/复位不动作，后续必须核实驱动板电路，设计默认关闭的硬件使能与下拉；不能直接用 GPIO 对抗 J1 固定高电平。


## 倒装相机与自适应转向

用户确认相机倒装，本机私有相机配置已经将 `vertical_flip`、`horizontal_mirror` 都设为 true。该文件被 Arduino 和 ESP-IDF 相机实现共用，之后重新编译任一入口都会采用此方向；两项同时翻转等效于 180° 校正，预览和检测框使用同一图像。ESP-IDF 初始化检查方向设置是否成功，失败时禁止相机/自主控制启动，串口输出实际配置值。

当前转向维持 80% 起转占空比，根据水平偏差大小调节持续时间：刚超过居中容差时约 100ms，靠近画面边缘时最多 350ms；绝对上限为 400ms，且必须短于画面过期时间。该上限不是转动角度，没有编码器与角速度标定，不能保证一次精确到位。若仍易过冲，先减小 `turn_max_ms`，不要提高 PWM 或取消新鲜帧/超时要求。前后移动的限时与原有停止保护保持有效。

重新编译刷写后，串口应显示 `Camera orientation: vflip=1 hmirror=1`。刷写期间关闭电机电源，先确认画面正立、实际左侧的手也在画面左侧，再在围挡区域验收转向。没有在本次修改中自动刷机或启动电机。


## 识别即吹风与网页状态

会话启用且目标有效时立即开启风扇，不再等待底盘对准。`/robot` 单独显示“已下发开启（转动未确认）”“已下发关闭”或“状态未知”；`fan_output_on` 是设备执行 GPIO 写入后的开关输出记录，写入失败时为 null，`fan_rotation_confirmed` 始终为 null，因为当前两线风扇没有转速反馈。网络错误时清除旧的开启显示，不用上一次状态假装设备仍在线。

网页显示开启但扇叶不转时，说明需要继续检查风扇电源、驱动模块和接线，不能据此断言物理风扇正在运行。刷写时关闭电机电池开关，刷完后再恢复电源并重新启用。


自动启动模式新增回归验证：无需心跳可超过 30 秒、停止不会被旧心跳恢复、无手/过期停止输出、自动模式网页切后台/关闭不发送停止、网络错误不谎报设备已停止、手动恢复不请求续租。模板 `settings.example.h` 保留 `auto_start = false`，本机已确认配置启用自动启动。
